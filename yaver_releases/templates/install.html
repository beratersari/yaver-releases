First install

Install Yaver

Download the package for this computer from the releases page. The zip is either an executable build or a full install zip. The steps below follow that shape. OpenCode and Codex are not inside the executable. The full install zip can install them.

Windows

Executable

The zip root contains yaver.exe, a folder named _internal, and .env.example.

  1. Extract the zip. Leave yaver.exe and _internal in the same folder.
  2. Copy .env.example to .env in that folder and set the Jira host, token, and board id.
  3. Run yaver.exe. It listens on port 8080.
  4. Open http://127.0.0.1:8080.

Install zip

The zip contains install-dashboard.bat at the top.

  1. Extract the zip.
  2. Run install-dashboard.bat, then install-backends.bat, then install-codex.bat.
  3. Edit .env. Set the Jira host, token, and board id.
  4. Run start.bat.
  5. Open http://127.0.0.1:8080. Open the OpenCode window only with start-opencode.bat from this folder.

Ubuntu 18.04, 20.04, 22.04, and 24.04

Download the Ubuntu version that matches the computer. An executable built on Ubuntu 24.04 does not start on 22.04 or older. Check with lsb_release -rs.

Executable

  1. Extract the zip. You should see yaver and _internal.
  2. Copy .env.example to .env and edit it.
  3. Run ./yaver start as the account that should own the work. Do not use root.
  4. Open http://127.0.0.1:8080 on that machine.

Install zip

  1. Extract the zip so install-dashboard.sh sits next to src and vendor.
  2. Run ./install-dashboard.sh, then ./install-backends.sh, then ./install-codex.sh.
  3. The Linux package sets YAVER_BASE_DIR=/var/tmp/yaver so every account can write there without sudo. Data is /var/tmp/yaver/yaver and clones are /var/tmp/yaver/t.
  4. Edit .env, then run ./start-backend.sh as that same user. Yaver and OpenCode serve have to be the same user. A systemd unit needs User= and Group=. Do not start either process with sudo.
  5. Open http://127.0.0.1:8080.

Update from Yaver

  1. Leave this site running on a PC the others can reach, for example http://192.168.1.20:8090.
  2. In Yaver, open Settings, then Runtime.
  3. Set the release server address and port. Save, then choose Check.
  4. Update closes Yaver, downloads the package for this Windows PC or this Ubuntu version, and starts Yaver again. Settings in .env stay. The data folder stays. A git checkout is left alone.

Publish the same kind of zip the computers already use. An executable install will not apply a full install zip, and a full install will not apply an executable zip.

Run this site

python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
copy .env.example .env
.venv\Scripts\python -m yaver_releases

On Linux, use python3 -m venv .venv, .venv/bin/pip, and .venv/bin/python -m yaver_releases. The default listen address is every interface on port 8090. Downloads are open on that port. The admin password is the only thing that protects uploads, so do not forward the port to the public internet.

Windows firewall, from an elevated prompt:

netsh advfirewall firewall add rule name="Yaver releases" dir=in action=allow protocol=TCP localport=8090

Ubuntu:

sudo ufw allow 8090/tcp
